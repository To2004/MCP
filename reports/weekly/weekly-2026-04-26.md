## 🛠️ Tools & MCP

### **Cowork Live Artifacts (announced April 20)**
Claude can now build artifacts in Cowork that stay connected to your apps and files. Open one a week later and it refreshes with current data — no re-prompting. Targets recurring dashboards (campaign performance, hiring pipeline, support queue, weekly metrics) instead of one-shot visuals.
**Do this now:** Identify the one report you regenerate every Monday morning. Ask Claude to turn it into a Live Artifact and pin it. You'll save the weekly setup time forever.
[Source: Claude on X](https://x.com/claudeai/status/2046328619249684989) · [Frank's World analysis](https://www.franksworld.com/2026/04/24/revolutionizing-data-management-with-claude-cowork-live-artifacts/)

### **Claude Code Ultraplan now auto-provisions cloud env**
Earlier in April, Ultraplan required manual web-UI setup before your first remote run. Now `/ultraplan` and other remote-session features auto-create a default cloud environment. Workflow: prompt locally → Claude clones your repo to a cloud container → drafts an interactive plan in a web editor → review and run remotely or pull back local. Requires v2.1.101+, a GitHub repo, and Pro/Max.
**Do this now:** Next time you face a multi-file refactor, run `/ultraplan` instead of starting locally. The cloud planning step typically catches structural issues a local agent misses.
[Source: Better Stack guide](https://betterstack.com/community/guides/ai/claude-code-ultraplan/) · [Claude Code Week 15 release notes](https://code.claude.com/docs/en/whats-new/2026-w15)

### **Monitor tool: stop polling, start reacting**
The Monitor tool launches a shell command and turns its stdout into an event stream. Each line is a notification that wakes the main session — Claude reacts the moment a filter matches. Use cases: tail a log, watch a build, detect a file change, react to webhook output. Big token saver vs. polling loops.
**Do this now:** Replace any `while true; do tail -f ...; done` polling pattern in your agent scripts with a Monitor invocation.
[Source: claudefa.st guide](https://claudefa.st/blog/guide/mechanics/monitor)

### **New Claude Code slash commands**
Recent additions to the CLI: `/loop` self-paces when you omit the interval, `/team-onboarding` packages your local Claude Code setup into a replayable guide for a new teammate, `/autofix-pr` enables PR auto-fix from your terminal, and `/recap` provides context when returning to an old session (also configurable via `/config`). The MCP tool output limit also bumped from default to **500,000 characters**.
**Do this now:** Run `/team-onboarding` once and save the output to your team's onboarding doc — it's the fastest "ramp the new hire" artifact you can ship.
[Source: Claude Code changelog](https://claudefa.st/blog/guide/changelog)

## 💡 Prompting Tips

### **"Grill me on these changes" — make Claude your reviewer (Boris Cherny)**
The Claude Code creator's go-to pattern: tell Claude *"Grill me on these changes and don't make a PR until I pass your test."* Inverts the usual loop — instead of you reviewing Claude's output, Claude probes your understanding before producing a PR. Catches sloppy thinking earlier and tends to produce more carefully scoped diffs.
**Do this now:** On your next non-trivial change, use the grill pattern before letting Claude open the PR. You'll likely cut at least one revision round.
[Source: Boris Cherny on Threads](https://www.threads.com/@boris_cherny/post/DUMZr4VElyb/im-boris-and-i-created-claude-code-i-wanted-to-quickly-share-a-few-tips-for)

### **Use voice dictation — your prompts get more specific**
Boris's tip: people speak roughly 3× faster than they type, so dictated prompts naturally include more context, more "the reason I want this is…" framing, and fewer corner-cutting shortcuts. Built-in macOS/iOS dictation is enough.
**Do this now:** For your next 3 Claude Code sessions, dictate your initial prompt instead of typing. Compare output quality.
[Source: Boris Cherny on Threads](https://www.threads.com/@boris_cherny/post/DUMZr4VElyb/im-boris-and-i-created-claude-code-i-wanted-to-quickly-share-a-few-tips-for)

### **"Smallest set of high-signal tokens" — Anthropic's context-engineering rule**
Anthropic's official context-engineering guidance crystallized this quarter: the goal is *the smallest set of high-signal tokens that maximize the likelihood of your desired outcome.* Stuffing more context, more examples, and more rules generally hurts on 4.6+/4.7-class models. Trim aggressively.
**Do this now:** Audit your most-used system prompt. Delete one section, run a few representative tasks, and check if quality drops. Most teams find they can cut 30%+ without quality loss.
[Source: Anthropic — Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)

### **Heads-up on hidden "switch" prompts (`L99`, `/ghost`, `/deepthink`)**
Community tinkerers have published "hidden" prompt prefixes — `L99` claims to switch into a deeper, less-hedged response mode; `/ghost` claims to strip AI-tells like "Here's what I think" and "It's worth noting"; `/deepthink` claims to force layered reasoning. These are *unofficial* community discoveries, not Anthropic-supported features — they may stop working after any model update. Try them on low-stakes prompts before relying on them.
**Do this now:** Test `/ghost` on a draft you'd otherwise heavily edit for AI-isms. If it cuts your edit time, keep it in your toolbox; treat as a temporary trick, not a stable feature.
[Source: CLSkills](https://clskillshub.com/blog/7-hidden-claude-prompts-that-work)
