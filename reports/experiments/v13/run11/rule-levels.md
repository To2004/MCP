# Input Rule Levels: run11

Every kept input, and which of its values land on each level from 1 to 5 at run time. Generated by `scripts/render_input_rule_levels.py`; do not edit by hand.

## How to read it

- **Reads**: what the rule looks at in the value: a number (and which number), an asset name, words the text contains, a fixed value, or an email or URL domain.
- **Levels**: 1 safest, 2 safe, 3 ordinary, 4 high, 5 critical; an ordinary call gets 1 to 3. `(default)` marks the level a value gets when nothing more specific matches.
- **If left out**: the level when the call omits the input; `adds nothing` means omitting it does not raise the call.
- **Levels from**: `scan` each asset's scanned sensitivity, which a `register` rule returns for a value naming that asset; `agent name words` name fragments the agent added for the levels no asset reaches; `policy` the organization's policy (v12 tables, or the address lists of the email ladder); `policy overrides` assets the policy raises above their scanned level (v12); `schema` the tool's own bounds (v12); `agent` the agent's own judgement.
- A `register` row lists every asset the tool can reach, including abstract ones (a directory, a record set) that a value rarely names. Opaque ids (`C0BL...`) match only through the deployment's id table, otherwise they take the default.
