# Scoring_curated — Papers Strictly About Automated Risk Scoring

Curated 2026-05-05 for the thesis's **defense-oriented MCP risk-scoring framework** (MCP server = protected asset; agents = threat source; static + dynamic scoring of incoming requests).

Strict inclusion rule: every paper here either **produces** or **studies** a numeric/graded score, probability, or rank for tools, assets, messages, agents, or accesses. Papers that only describe threats, taxonomies, attacks, or defenses without a scoring mechanism are excluded.

14 PDFs in this folder, organized into 6 categories. One additional MDPI paper (Trust Score-Based Access Control Model for ZTA, 2025) is referenced below but could not be downloaded; access via https://www.mdpi.com/2076-3417/15/17/9551.

## 1. MCP-specific risk scoring

**What this category does:** Score MCP servers, tools, or messages directly. These are the closest existing analogues to the thesis — they take an MCP artifact (server repo, tool description, log line) as input and emit a risk number or label that can drive a gate/throttle/deny decision.

### MCP-in-SoS — Risk assessment framework for open-source MCP servers

- arXiv:2603.10194 (2026)
- File: `2026_MCP-in-SoS-risk-assessment-mcp-servers.pdf`
- 4-stage pipeline: static analysis → CWE/CAPEC metadata → normalize → assign per-finding **Risk Index** + repo-level risk score. Evaluated on 222 GitHub MCP repos.
- Closest existing system to the **static** side of this thesis.

### MCP-RiskCue — Can LLMs infer risk from MCP server logs?

- arXiv:2511.05867 (2025)
- File: `2025_MCP-RiskCue-llm-infer-risk-from-logs.pdf`
- Synthetic benchmark testing whether LLMs can reason about security risk from MCP server system logs.
- Relevant for the **dynamic** side — scoring based on observed runtime telemetry, not static metadata.

### Auditing MCP Servers for Over-Privileged Tool Capabilities

- arXiv:2603.21641 (2026)
- File: `2026_auditing-mcp-servers-overprivileged-tools.pdf`
- `mcp-sec-audit`: scores capability-based deployment risk by analyzing both implementation code and tool metadata; outputs hardening guidance.
- Direct analogue for scoring tool *permissions* (least-privilege violations) at registration time.

## 2. Vulnerability scoring (CVSS automation)

**What this category does:** Convert a free-text vulnerability description into a numeric severity score (CVSS v3.1) using LLMs or transformers. Methodologically the closest mature analogue: same input shape (free-text) → same output shape (score) we want for tool/message scoring.

### From Description to Score: Can LLMs Quantify Vulnerabilities?

- arXiv:2512.06781 (2025)
- File: `2025_from-description-to-score-llm-cvss.pdf`
- Tests GPT-4o, GPT-5, Llama-3.3, Gemini-2.5-Flash, DeepSeek-R1, Grok-3 on CVSS v3.1 scoring across 31k+ CVEs. Reports per-metric accuracy and class-imbalance failure modes.

### Can LLMs Classify CVEs? Computing CVSS Vectors

- arXiv:2504.10713 (2025)
- File: `2025_can-llms-classify-cves-cvss-vectors.pdf`
- Compares LLMs vs. embedding-based methods for predicting CVSS vector components; argues for a hybrid (LLM + embedding) pipeline.

## 3. Permission and tool-invocation risk scoring

**What this category does:** Score either (a) the risk of *granting* a permission/tool capability up front (static), or (b) the risk of a *specific tool invocation* at runtime (dynamic). Most directly maps to the thesis's two scoring phases.

### Detecting Malicious Entra OAuth Apps with LLM-Based Permission Risk Scoring

- arXiv:2512.15781 (2025)
- File: `2025_llm-permission-risk-scoring-entra-oauth.pdf`
- Public dataset of risk scores for all 769 Microsoft Graph permissions/scopes, generated by 8 open-source LLMs with reasoning. Evaluates LLM-as-scorer.
- Direct methodological template for the thesis's **static** scoring of MCP tool permissions.

### AgenTRIM — Tool Risk Mitigation for Agentic AI

- arXiv:2601.12449 (2026)
- File: `2026_AgenTRIM-tool-risk-mitigation-agentic-ai.pdf`
- Runtime tool orchestrator that combines deterministic controls + LLM reasoning to score tool exposure on a per-query basis and validate high-risk tool invocations.
- Direct match for the **dynamic** side.

### Agent Tools Orchestration Leaks More — Dataset, Benchmark, Mitigation

- arXiv:2512.16310 (2025)
- File: `2025_agent-tools-orchestration-leaks-more.pdf`
- Introduces **Risk Leakage Rate (RLR)** and **H-Score** metrics to quantify how risk leaks across tool orchestration. Reports 90.24% average RLR across eight models.
- Provides ready-made metrics to evaluate the thesis's framework end-to-end.

## 4. Anomaly severity scoring

**What this category does:** Score events on a graded severity scale rather than binary normal/anomaly. Critical for translating raw anomaly detection output into actionable thresholds (allow / log / throttle / deny).

### Are Anomaly Scores Telling the Whole Story? — Multilevel Anomaly Detection (MAD) Benchmark

- arXiv:2411.14515 (2024)
- File: `2024_multilevel-anomaly-detection-benchmark.pdf`
- Argues binary anomaly scores miss real-world severity. Proposes MAD where the score reflects practical severity, plus a benchmark to evaluate models on graded severity.
- Direct guidance for shaping the framework's score output.

### Few-Shot API Attack Anomaly Detection in a Classification-by-Retrieval Framework

- arXiv:2405.11247 (2024)
- File: `2024_few-shot-api-attack-anomaly-detection.pdf`
- Retrieval-based anomaly scoring for API requests with very few labelled attack examples. Useful when attack data is scarce.
- Closely matches the **dynamic** scoring of inbound MCP messages.

## 5. Agent action harm and safety scoring

**What this category does:** Score an agent's *action* or *trajectory* for harm, safety violation, or probability of reaching an unsafe state. End-to-end behavioural scoring — complementary to per-message scoring.

### AgentHarm — Benchmark for Measuring Harmfulness of LLM Agents

- arXiv:2410.09024 (ICLR 2025)
- File: `2024_AgentHarm-llm-agent-harmfulness-benchmark.pdf`
- 110 explicitly malicious agent tasks (440 with augmentations) across 11 harm categories. Introduces **HarmScore** + **RefusalRate** metrics for tool-calling agents under attack.
- Reference benchmark for tuning the dynamic-scoring threshold against realistic harmful tasks.

### Agent-SafetyBench — Evaluating the Safety of LLM Agents

- arXiv:2412.14470 (2024)
- File: `2024_Agent-SafetyBench-llm-agent-safety.pdf`
- 349 interaction environments and 2,000 test cases spanning 8 safety-risk categories and 10 common failure modes. Scores agents per category.
- Failure-mode taxonomy maps onto categories the thesis's framework must distinguish.

### ProGuard — Proactive Runtime Enforcement of LLM Agent Safety via Probabilistic Model Checking

- arXiv:2508.00500 (2025)
- File: `2025_ProGuard-probabilistic-runtime-llm-safety.pdf`
- Abstracts agent behavior into a Discrete-Time Markov Chain learned from execution traces. At runtime, estimates **probability of reaching an unsafe state**; intervenes when the score exceeds a user-defined threshold.
- Probabilistic-formal alternative for the **dynamic** scoring layer.

## 6. Trust scoring (zero-trust access)

**What this category does:** Compute a numeric trust score per access request or principal, then use it as input to an authorization decision. Architectural pattern the whole MCP-scoring framework slots into.

### Zero Trust Score-based Network-level Access Control in Enterprise Networks

- arXiv:2402.08299 (2024)
- File: `2024_zero-trust-score-network-access-control.pdf`
- Lists 29 trust attributes; introduces a Subjective-Logic-based algorithm to compute a numeric trust score from them; offers fine-grained authorization decisions.

### A Trust Score-Based Access Control Model for Zero Trust Architecture (Sensitivity Analysis & Real-World Eval) — *not downloaded*

- MDPI Applied Sciences 15(17):9551 (2025)
- Link: https://www.mdpi.com/2076-3417/15/17/9551
- Proposes a Trust Score (TS) computed from User Behavior, Network Environment, Device Status, and Threat History. Includes sensitivity analysis and real-world performance evaluation.
- Listed for completeness; download attempt failed (HTML wrapper). Open-access; can be retrieved manually.

## 7. Asset / data importance scoring

**What this category does:** Score the **asset itself** (a file, dataset, system, or business resource) for criticality, sensitivity, or business value — independent of any specific request. In the thesis, this is what gets multiplied with the request-side score to decide whether a given action on that asset is acceptable. Without asset scoring, a generic "low-risk read" looks the same whether it touches a temp file or a payroll database.

### CJA-RL — Crown Jewels Analysis using Reinforcement Learning with Attack Graphs

- arXiv:2108.09358 (2021)
- File: `2021_CJA-RL-crown-jewels-reinforcement-learning-attack-graphs.pdf`
- Trains an RL agent on the network's attack graph to automatically identify which assets are the "crown jewels" — i.e., the highest-criticality nodes. Outputs ideal entry points, choke points, and pivots, scoring every node by its strategic importance.
- Direct analogue for scoring **which files/resources** an MCP server protects matter most.

### SARA — Sensitivity-Aware Relevance Assessments

- arXiv:2401.05144 (2024)
- File: `2024_SARA-sensitivity-aware-relevance-assessments.pdf`
- Trains SVM/Logistic-Regression sensitivity classifiers on TF-IDF features, then proposes a **Learning-to-Rank** approach that produces a numeric sensitivity score per document and integrates a sensitivity-optimized loss. Yields a graded sensitivity score, not just a label.
- Direct method for the thesis's filesystem-MCP use case — score every file on disk by sensitivity.

### CIA+TA Risk Assessment for AI Reasoning Vulnerabilities

- arXiv:2508.15839 (2025)
- File: `2025_CIA-TA-risk-assessment-ai-reasoning-vulnerabilities.pdf`
- Extends the classic CIA triad (Confidentiality / Integrity / Availability) with a **TA** (Trust / Accountability) dimension and produces per-asset risk scores along all four axes for AI-reasoning systems.
- Provides a structured score schema (per-axis, not single number) the thesis can adopt for asset-side output.

### Securing Critical Infrastructure in the AI Era — Automated AI-Based Security Framework

- arXiv:2507.07416 (2025)
- File: `2025_securing-critical-infrastructure-ai-era-framework.pdf`
- Computes a **dynamic impact score** per vulnerability that combines CVSS severity, asset criticality, exploit activity, dependency-graph position, and environmental exposure — i.e., couples vulnerability scoring with asset-criticality scoring at runtime.
- Closest existing system to the thesis's static × dynamic multiplication.

### A Framework for Data Valuation and Monetisation

- arXiv:2512.07664 (2025)
- File: `2025_data-valuation-monetisation-framework.pdf`
- General data-asset valuation framework: extracts data features and produces a numeric value score per dataset, intended for marketplaces and governance. Method-agnostic to the specific signal set.
- Useful as the "what's this asset worth?" input alongside sensitivity — a data-asset's *value* is a separate axis from its *risk*.

## How the categories fit together

The 7 categories cover the full pipeline of the thesis's framework:

| Question | Category |
|---|---|
| **What** to score (the MCP target) | 1 — MCP-specific |
| **What** to score (the asset / file / dataset) | 7 — Asset / data importance |
| **What** to score (vulnerability artifacts) | 2 — CVSS automation |
| **When/how** to score (static, before invocation) | 3 — Permission scoring (static side) |
| **When/how** to score (dynamic, at request time) | 3 — Tool-invocation, 4 — Anomaly, 5 — Agent action |
| **Architectural pattern** | 6 — Trust score as policy input |

Cats 1, 2, 3-static, 7 are the static-scoring side. Cats 3-dynamic, 4, 5 are the dynamic-scoring side. Cat 6 is the architectural umbrella.

The thesis's effective score is roughly: **risk = f(asset_score [Cat 7] × request_score [Cat 3-5] × policy [Cat 6])** — Cat 7 is the multiplier that was missing before.
