## 🔧 API & SDK
### **Agent SDK billing split paused — subscriptions unchanged**
The plan to move automated Agent SDK / `claude -p` / third-party app usage onto a separate capped credit ($20 Pro → $200 top-tier) was pulled on June 15, the day it was due to land. The-decoder and DevOps.com tie the reversal to developer backlash, OpenAI's looming API price cuts, and Anthropic's IPO paperwork.
**Do this now:** If you re-architected billing last week, revert — your subscription pool covers agent usage again. But treat it as "for now," not permanent.
[Source](https://the-decoder.com/anthropic-backs-off-unpopular-billing-overhaul-as-price-war-with-openai-looms/)

### **Workload Identity Federation now generally available (June 17)**
WIF brings keyless authentication across all Claude API endpoints, first-party SDKs, and Claude Code. It works with any OIDC-compliant identity provider and adds service accounts so each workload gets its own identity, roles, and audit trail instead of a shared static key.
**Do this now:** Inventory where you still embed static `ANTHROPIC_API_KEY` values in CI/CD and services, then pilot WIF + a service account on one workload to kill the long-lived secret.
[Source](https://claude.com/blog/workload-identity-federation)

### **New tool versions: code execution, web search, web fetch**
The Developer Platform shipped `code_execution_20260521` (exposing the 90-second-per-cell limit for long-running code), plus `web_search_20260318` and `web_fetch_20260318`. A new `response_inclusion` option trims consumed result blocks to keep agentic context lean.
**Do this now:** If your agents run long code cells or rack up tokens replaying tool results, pin the new tool versions and turn on `response_inclusion`.
[Source](https://releasebot.io/updates/anthropic/claude-developer-platform)

### **Claude Opus 4.1 deprecated — retires August 5, 2026**
`claude-opus-4-1` entered the deprecated state with a hard retirement date of August 5. (This follows the Sonnet 4 / Opus 4 retirements that landed last week.)
**Do this now:** Grep for `claude-opus-4-1` in your pipelines and plan a migration to `claude-opus-4-8` well before August 5.
[Source](https://releasebot.io/updates/anthropic/claude-developer-platform)

## 🛠️ Tools & MCP
### **Claude Code: `/cd`, `--safe-mode`, and destructive-command guardrails**
The latest releases add `/cd` to move a live session to a new working directory without rebuilding the prompt cache (the new dir's CLAUDE.md is appended, and `--resume`/`--continue` follow it). `--safe-mode` boots with all customizations disabled for troubleshooting. Destructive ops are now blocked unless you asked for them: `git reset --hard`, `git checkout -- .`, `git clean -fd`, `git stash drop`, un-asked `git commit --amend`, and `terraform/pulumi/cdk destroy`.
**Do this now:** Use `/cd` instead of restarting sessions when you jump repos, and lean on the new git guardrails rather than your own pre-commit safety hooks.
[Source](https://code.claude.com/docs/en/whats-new)

### **`fallbackModel` and doubled rate limits**
You can now configure up to three fallback models tried in order when your primary is unavailable. Separately, Claude Code rate limits were doubled and Opus API limits raised — both live now.
**Do this now:** Set a `fallbackModel` chain (e.g., Opus → Sonnet) so long agent runs don't hard-fail on a single model hiccup.
[Source](https://releasebot.io/updates/anthropic/claude-code)

### **MCP spec release candidate published (final ships July 28)**
The next Model Context Protocol spec RC is out, featuring a stateless protocol core, an Extensions framework, Tasks, MCP Apps (interactive HTML UIs in sandboxed iframes), authorization hardening, and a formal deprecation policy. The final spec lands July 28, 2026.
**Do this now:** If you maintain an MCP server, read the RC now and check whether the stateless core or new auth rules affect your implementation before the July 28 cutover.
[Source](https://blog.modelcontextprotocol.io/posts/2026-07-28-release-candidate/)

### **Enterprise-managed MCP connector access (starting with Okta)**
Admins can provision MCP connectors once and users get zero-touch access on first login, with centralized authorization spanning Claude chat, Claude Code, and Cowork on Team and Enterprise plans.
**Do this now:** If you run an org on Okta, pilot enterprise-managed connectors to stop chasing individual users through per-connector OAuth.

## 💡 Prompting Tips
### **Pin tool versions in your prompts/configs, not just model IDs**
With the platform now shipping dated tool versions (`code_execution_20260521`, `web_search_20260318`, etc.), unpinned agent configs can silently shift behavior when defaults roll forward. Treat tool versions like model IDs: pin them explicitly so your evals stay reproducible.
**Do this now:** Add the exact tool-version strings to your agent definitions and note them next to your model ID in your prompt/config docs.
[Source](https://releasebot.io/updates/anthropic/claude-developer-platform)

### **State the *why*, and let high-effort models own multi-step work**
Still the highest-leverage habit on current models: give the purpose behind a task and set effort to high/xhigh rather than scripting every step. "Refactor to dependency injection *so we can mock the network layer in tests*" reliably beats the bare instruction.
**Do this now:** Add one sentence of motivation to your next non-trivial prompt and compare how many follow-ups it takes.
[Source](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices)
